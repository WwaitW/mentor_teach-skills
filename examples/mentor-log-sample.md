**涉及知识点：**

- 缺失值处理策略（理解中 △）
- 数据类型转换与校验（待巩固 ✗）

**考察记录：**

- Q1：用自己的话解释 `dropna()` 和 `fillna()` 的选择依据是什么？
  - 用户回答摘要：dropna 是直接删除，fillna 是填充默认值，业务上重要的字段用 fillna
  - 评估：理解中 △（补充解释：选择策略还需考虑缺失比例——缺失 > 30% 的列通常整列删除更合理，而不是填充）

- Q2：如果数据源每天新增 100 万行，现有的逐行处理方式会有什么问题？你会怎么改？
  - 用户回答摘要：会很慢，可以用多线程
  - 评估：待巩固 ✗（重新讲解：Pandas 本身是单线程的，大数据场景应考虑向量化操作或切换到 Polars/Dask，多线程在 IO 密集型场景有效，但 CPU 密集型的数据变换受 GIL 限制）

**拓展思考：**
- 了解 Polars 与 Pandas 的性能差异：Polars 使用 Rust 实现，原生多线程，处理大数据集时通常快 5-10 倍。可以尝试用 Polars 重写这个模块，对比性能差异。

## API 接口模块 — 2026-05-20

**涉及知识点：**

- Pydantic 数据校验（已掌握 ✓）
- HTTP 状态码语义（理解中 △）

**考察记录：**

- Q1：FastAPI 的依赖注入（`Depends`）解决了什么问题？不用它会怎样？
  - 用户回答摘要：Depends 可以复用代码，比如每个接口都需要验证 token，用 Depends 就不用每个函数都写一遍
  - 评估：已掌握 ✓

- Q2：POST 创建资源成功后应该返回 200 还是 201？区别是什么？
  - 用户回答摘要：都可以，200 就行
  - 评估：理解中 △（补充：201 Created 表示资源被新创建，语义更准确；200 OK 表示请求成功但不特指创建。遵循 REST 语义有助于 API 使用者理解操作结果，尤其是在有 API 文档的团队协作场景）

**拓展思考：**
- 探索 RFC 7231 中定义的 HTTP 语义：为什么 DELETE 成功推荐返回 204 而非 200？幂等性（idempotency）在 REST 设计中意味着什么？
